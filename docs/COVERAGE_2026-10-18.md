# Coverage and correctness survey, 2026-10-18

ROM CRC32: `C0AECDCA`. SHA-256: `dd94308d822636c6ddf73c5e2644c84f2eb8fb4d9201150fc5f37d44d6f423f1`.

Framework: snesrecomp `48982940` (PRs #183 and #184), with recursively updated main/master dependencies. Generation policy lives in `recomp/generate.toml`; `tools/regen.sh` delegates to the framework. The recipe applies to developer regeneration and the launcher SDK. Generated C is never edited by hand or committed.

This game had only a Japanese retail release; the original Japan ROM is the approved input. Story surveys use documented PAR health/energy assists and sample nine opponent/task states in the widened renderer (342-pixel captures).

The round timer at $060C is reused during transitions. An assist must only cap a live arena clock, never refill zero or freeze an inter-round countdown. Likewise, an opponent/task substate is not an ordered stage number. The survey does not yet certify the full story ending.

Apparent frame-step stalls were investigated with a zero-AOT control. Explicit server timeout replies left the original step pending; bounded read-only polling observed completion. The shared FrameDriver now handles this without repeating the mutation. The speculative IRQ-hold change was removed. Native IRQ deadline guards are unchanged by this release.

Releases remain setup packs: no ROM or generated game code is packaged. The player's Generate & Build flow consumes the same generation recipe as tools/regen.sh.

The post-Epyon snapshot investigation found a real file-save defect: the title chunk preserved the resume cursor but omitted the recompiled CPU and shared bridge/APU/scheduler state. A real-ROM test failed its CPU-clock restore assertion before the fix. The game now uses RtlSaveExecutionState/RtlLoadExecutionState/RtlApplyExecutionState, with a versioned integrity envelope that rejects incomplete old saves and mismatched file-state identities before guest restoration. This intentionally breaks compatibility with old incomplete save files; it does not change the netplay build identity or establish cross-build compatibility.

Configure with `-DGWED_STATE_TESTS=ON`, build `gwed_state_tests`, then run `python tests/run_state_tests.py <executable> <owned-ROM>`. The suite checks complete memory/file replay, rollback replay, restart into a new process, and atomic rejection of unguarded or corrupted states. It opens no output audio device.

Automated runs use a dummy output audio device while preserving audio emulation. Release defaults retain normal audio. Private ROMs, full memory captures, journals, and trial profiles remain outside the repository. A successful build or version string alone is not evidence of cross-build netplay compatibility.

Setup-pack generation also requires the native analyzer. The updated shared packager includes it and smoke-tests the staged SDK, so the bundled Python/C++ tools can generate without a Rust installation.
